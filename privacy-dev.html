01 — Overview

Overview

↯ Architectural Guarantee

Dhurta Developer Browser collects nothing about you, your sessions, or the applications you test. No usage metrics, no crash reporting, no session replays, no request logs sent anywhere. All DevTools data, profiler output, and intercepted traffic lives exclusively on your machine.

Dhurta Developer Browser extends the standard Dhurta Browser with an expanded toolset: network request interception, response mocking, a performance profiler, a local certificate authority, and enhanced DevTools panels. Each of these features processes data locally only. None of them have a remote component that receives your data.

The source code is public at github.com/prashantkeshr/Dhurta. Every statement in this policy can be verified by auditing the codebase.

03 — Local Storage

Data Stored Locally on Your Device

The Developer Browser writes the following to your local profile directory. Everything is in standard, readable formats and is never transmitted anywhere:

  • Browsing & test history (SQLite)
  • Bookmarks (JSON)
  • Saved passwords and credentials (OS-level encrypted credential store)
  • Browser settings and DevTools workspace configuration (JSON)
  • Network mock rules and response overrides (JSON)
  • Local CA private key and issued certificates (PEM, in a sandboxed certs directory)
  • Breakpoint configurations and workspace source maps
  • Custom DevTools themes and panel layouts
  • Extension data
  • Cache and site data (clearable at any time)
↳ Transparency Dashboard

Open dhurta://transparency to see the exact path and size of every file the browser has written to your disk. You can inspect, export, or delete any entry from that page.

04 — DevTools & Profiler

Developer Tools & Profiler

The Developer Browser ships with an expanded toolset beyond the standard Chromium DevTools. Here is how each component handles data:

Network Inspector

The Network Inspector logs all requests made by the pages you load. This log is held in memory for your current session and is never sent anywhere. You can export it as HAR at any time. The log clears when you close the tab or end the session, unless you explicitly save it.

Performance Profiler

Performance traces are captured entirely in memory. Trace files are only written to disk when you click "Save profile." They are never uploaded, shared, or indexed.

Local Certificate Authority

The built-in CA generates a private key stored in your profile directory. The key never leaves your machine. Certificates issued by it are trusted only within this browser instance and are not registered with any public certificate transparency log.

↳ Important — HTTPS Inspection

When HTTPS inspection is enabled, the browser terminates and re-encrypts TLS connections locally. The decrypted content is processed only in local memory. No decrypted content is written to disk or sent off-device.

05 — Proxy & Intercept

Proxy Mode & Request Interception

The Developer Browser can act as a local proxy, intercepting and optionally modifying HTTP/HTTPS traffic from the page under test. The following applies:

  • All intercepted traffic is processed locally in memory — it is never forwarded to any Dhurta server or third party.
  • Request/response bodies in the intercept queue are held in memory and discarded when the session ends unless you explicitly export them.
  • Mock rules and response overrides you configure are saved locally to your profile directory.
  • Proxy mode is scoped to the browser only — it does not intercept system-level traffic from other applications.
↳ Security Note

When testing applications that handle sensitive data, we recommend using a dedicated test environment and test credentials. Intercepted payloads containing real credentials or personal data are your responsibility to handle appropriately and clear when done.

06 — Ghost Mode & Tor

Ghost Mode & Tor Routing

Ghost Mode routes traffic through the Tor network and applies fingerprint spoofing. In the Developer Browser, Ghost Mode operates alongside DevTools:

  • Your real IP address is replaced by a Tor exit node address visible to the target server.
  • Ghost Mode sessions are in-memory only — no history, cache, or cookies are written to disk during a Ghost Mode session.
  • The Network Inspector continues to function in Ghost Mode, logging requests locally only.
  • WebRTC is disabled during Ghost Mode to prevent IP leaks.
  • Browser fingerprint is spoofed (canvas, audio, WebGL, fonts, platform strings).

Dhurta has no visibility into which sites you visit through Tor. The Tor network is operated by independent volunteer relays outside Dhurta's control.

07 — Third Parties

Third-Party Services & Integrations

The Developer Browser does not embed analytics, crash reporting, or telemetry SDKs of any kind. The following third-party interactions occur only on your explicit instruction:

  • Websites and APIs you navigate to or test with are subject to their own privacy policies.
  • Extensions you install from the Chrome Web Store are third-party software — Dhurta is not responsible for their data practices.
  • Search queries are sent to whichever search engine you have configured — not to Dhurta.

The Developer Browser does not include:

  • Google Analytics or any analytics SDK
  • Sentry, Bugsnag, or any crash reporting service
  • Advertising networks or tracking pixels
  • Cloud-synced DevTools sessions or remote profiling endpoints
  • Any data broker or identity resolution service
08 — Updates

Software Updates

The Developer Browser checks for new versions by making a request to GitHub Releases. This request contains no user identifier, device identifier, or personal data — it is a plain HTTPS GET to a public endpoint. The check can be disabled in Settings → Developer → Updates.

Update packages are distributed through GitHub Releases or the Microsoft Store. Dhurta does not operate its own update infrastructure.

09 — Your Rights

Your Rights & Control

Because all data is local, you have complete, immediate control at all times:

  • Inspect: dhurta://transparency lists every file the browser has written to your disk with its path and size.
  • Clear: Settings → Privacy → Clear Browsing Data removes history, cookies, cache, mock rules, and any saved DevTools sessions.
  • Export: Export bookmarks, network logs (HAR), and profiler traces from their respective panels at any time.
  • Portable: Your profile directory is a standard filesystem folder — back it up, copy it, or move it freely.
  • Erase: Uninstall the browser and delete your profile directory to remove all stored data. There is no server-side data to request deletion of.

There is no account to delete, no data deletion form, and no support ticket needed — because nothing was ever sent to us.
