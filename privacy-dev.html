01 — Introduction

Introduction

Architectural Guarantee

Dhurta Developer Browser collects nothing about you, your sessions, or the applications you test. No usage metrics, no crash reporting, no session replays, no request logs sent anywhere. All DevTools data, profiler output, intercepted traffic, and certificate authority data lives exclusively on your machine.

This Privacy Policy governs the data practices of Dhurta Developer Browser — Black Edition, a professional tooling browser designed for developers, QA engineers, and security researchers. The Developer Browser extends the standard Dhurta Browser with an expanded toolset: network request interception, response mocking, a performance profiler, a local certificate authority, and enhanced DevTools panels.

Each of these additional features processes data locally only. None of them have a remote component that receives your data. This policy documents every data touchpoint in the Developer Browser — including those unique to developer tooling — with the same transparency we bring to network request inspection.

All claims in this policy can be verified by auditing the public source code at github.com/prashantkeshr/Dhurta.

05 — Local Storage

Information Stored Locally on Your Device

The Developer Browser writes the following to your local profile directory. Everything is in standard, readable formats and is never transmitted anywhere:

  • Browsing & test history: URLs, page titles, and visit timestamps stored in a local SQLite database.
  • Bookmarks: Saved bookmarks and folder structure stored as JSON.
  • Saved passwords and credentials: OS-level credential store (Windows Credential Manager, macOS Keychain, Linux Secret Service). Raw passwords never stored in plaintext.
  • Browser settings and DevTools workspace configuration: JSON files in your profile directory.
  • Network mock rules and response overrides: Configurations for request interception saved as JSON in your profile directory.
  • Local CA private key and issued certificates: PEM files in a sandboxed certs subdirectory of your profile. The private key never leaves your machine.
  • Breakpoint configurations and workspace source maps: DevTools project settings stored locally.
  • Custom DevTools themes and panel layouts: UI preference settings stored locally.
  • Extension data: Local data stored by extensions you install.
  • Cache and site data: Page caches, cookies, localStorage — fully clearable at any time from Settings.

06 — DevTools & Profiler

Developer Tools & Performance Profiler

The Developer Browser ships with an expanded toolset beyond the standard Chromium DevTools. Here is exactly how each component handles data:

Network Inspector

The Network Inspector logs all requests made by the pages you load. This log is held in memory for your current session and is never sent anywhere. You can export it as a HAR file at any time. The log clears when you close the tab or end the session, unless you explicitly save it.

Performance Profiler

Performance traces are captured entirely in memory. Trace files are written to disk only when you click "Save profile." They are never uploaded, shared, or indexed anywhere. Profiler traces may contain information about the internal architecture of the application you are testing — this data is yours alone.

Console & Log Inspector

Console output from pages you test is held in session memory and never transmitted. Logs may contain sensitive information from the applications you are testing — the Developer Browser does not read, filter, or report on console content.

Source Debugger & Breakpoints

Source maps, breakpoint configurations, and workspace settings are stored locally in your profile directory. No debugger session data is transmitted to Dhurta.

Sensitive Application Data

When testing applications that handle authentication tokens, payment data, or personal information, that data may appear in DevTools panels (network requests, console output, local storage viewers). The Developer Browser does not read or report on this data, but you are responsible for handling intercepted payloads appropriately and clearing sensitive data when done.

07 — Proxy & Intercept

Proxy Mode & Request Interception

The Developer Browser can act as a local proxy, intercepting and optionally modifying HTTP/HTTPS traffic from the page under test. This is one of the more sensitive features from a data-handling perspective. The following applies without exception:

  • All intercepted traffic is processed locally in memory. It is never forwarded to any Dhurta server or third party.
  • Request and response bodies in the intercept queue are held in memory and discarded when the session ends unless you explicitly export them.
  • Mock rules and response overrides you configure are saved locally to your profile directory only when you save them.
  • Proxy mode is scoped to the browser's renderer processes only — it does not intercept system-level traffic from other applications on your machine.
  • When HTTPS inspection is enabled, the browser terminates and re-encrypts TLS connections locally using the Local CA. The decrypted content is processed only in local memory and is never written to disk or transmitted.
Security Responsibility

You are responsible for the security of data intercepted through Proxy Mode. Intercepted payloads may contain API keys, authentication tokens, session cookies, and personal data from the applications you test. Use test environments with test credentials wherever possible, and clear sensitive intercepted data when your testing session is complete.

08 — Local Certificate Authority

Local Certificate Authority (Local CA)

The Developer Browser includes a built-in Local Certificate Authority for HTTPS inspection and development certificate management. The following applies:

  • The CA private key is generated on your device and stored in your profile directory in an encrypted format. It never leaves your machine.
  • Certificates issued by the Local CA are trusted only within this browser instance for the duration of your DevTools session.
  • Issued certificates are not registered with any public certificate transparency log. They are strictly local.
  • The Local CA root certificate, if you choose to export and install it into your OS trust store, is your own certificate — Dhurta has no copy of it.
  • The Local CA is scoped to developer testing. Certificates issued by it are not publicly trusted and cannot be used for production TLS.
Certificate Security

The Local CA private key is as sensitive as any private key. Do not share your profile directory, back it up to unencrypted cloud storage, or export the CA private key to external systems. If your Local CA private key is compromised, regenerate it from DevTools → Certificate Authority → Regenerate CA.

09 — Ghost Mode & Tor

Ghost Mode & Tor Routing

Ghost Mode routes traffic through the Tor network and applies fingerprint spoofing. In the Developer Browser, Ghost Mode operates alongside DevTools:

  • Your real IP address is replaced by a Tor exit node address visible to the target server.
  • Ghost Mode sessions are in-memory only — no history, cache, or cookies are written to disk during a Ghost Mode session.
  • The Network Inspector continues to function in Ghost Mode, logging requests locally only.
  • WebRTC is disabled during Ghost Mode to prevent IP leaks.
  • Browser fingerprint is spoofed (canvas, audio, WebGL, fonts, platform strings, hardware concurrency).

Dhurta has no visibility into which sites you visit through Ghost Mode. The Tor network is operated by independent volunteer relays outside Dhurta's control. For complete confidence in your anonymity during sensitive testing, verify your protection status using the Omni Dashboard at dhurta://omni.

10 — Cookies & Tracking

Cookies & Tracking Technologies

Cookies set by applications you test

Like all browsers, the Developer Browser allows websites to set cookies. These cookies are managed by the browser and are subject to the privacy policies of the websites that set them. Dhurta does not read, intercept, or transmit cookies.

Chakra Shield (inherited from Dhurta Browser) blocks third-party tracking cookies by default. This can be temporarily disabled for testing purposes in DevTools → Network → Disable Chakra Shield.

Dhurta-set cookies

Dhurta Developer Browser itself does not set any cookies on external websites. Dhurta does not operate a cookie-based tracking infrastructure of any kind.

Do Not Track & Global Privacy Control

The Developer Browser supports both the Do Not Track (DNT) header and the Global Privacy Control (GPC) signal. Both can be enabled or disabled per-session for testing purposes in DevTools → Network → Headers.

11 — Third-Party Services

Third-Party Services & Integrations

The Developer Browser does not embed analytics, crash reporting, or telemetry SDKs of any kind. The following third-party interactions occur only on your explicit instruction:

  • Websites and APIs you navigate to or test with are subject to their own privacy policies.
  • Extensions you install from the Chrome Web Store are third-party software — Dhurta is not responsible for their data practices. Extensions that claim developer tool functionality should be evaluated carefully for their own network access.
  • Search queries are sent to whichever search engine you have configured — not to Dhurta.

The Developer Browser does not include:

  • Google Analytics or any analytics SDK
  • Sentry, Bugsnag, or any crash reporting service
  • Advertising networks or tracking pixels
  • Cloud-synced DevTools sessions or remote profiling endpoints
  • Any data broker or identity resolution service
  • Any third-party SDK that makes outbound network calls without your explicit instruction
12 — Software Updates

Software Updates

The Developer Browser checks for new versions by making a request to GitHub Releases. This request contains no user identifier, device identifier, or personal data — it is a plain HTTPS GET to a public endpoint. The check can be disabled in Settings → Developer → Updates.

Update packages are distributed through GitHub Releases or the Microsoft Store. Dhurta does not operate its own update infrastructure.

Version Check Endpoint

The update check URL is: https://github.com/prashantkeshr/Dhurta/releases/latest. You can verify this in the source code. No proprietary update server is involved.

13 — Security

Security Measures

  • OS-level credential encryption: Saved passwords and sensitive autofill data are encrypted using Windows DPAPI, macOS Keychain, or Linux Secret Service.
  • Local CA private key encryption: The CA private key is encrypted at rest using the same OS-level credential storage.
  • SQLite encryption: Profile databases containing sensitive session data are encrypted at rest.
  • Sandboxed process model: Browser tabs run in isolated renderer processes following Chromium's multi-process security architecture.
  • HTTPS enforcement: Chakra Shield upgrades connections to HTTPS wherever possible.
  • No plaintext credential storage: At no point are raw passwords or keys written to unencrypted files on disk.
  • Regular security updates: Security patches are released promptly as part of the normal update cycle.
Security Disclosure

To report a security vulnerability in Dhurta Developer Browser, contact contact@dhurta.org. We treat all security reports as high-priority and provide initial acknowledgement within 24 hours. Developer tooling bugs that could expose intercepted data or compromise the Local CA are treated as critical severity.

14 — Children's Privacy

Children's Privacy

Dhurta Developer Browser is a professional development tool. While we do not collect personal data from anyone, the Developer Browser's tooling capabilities (network interception, proxy mode, certificate inspection) are intended for professional use by adults in development and testing contexts.

Dhurta does not knowingly collect personal information from children under the age of 13 (US), 16 (EU), or the minimum age defined by applicable law in other jurisdictions. Because we collect no personal data at all, this standard is met categorically.

If you believe a child under the applicable minimum age has transmitted personal data to us, please contact us immediately at contact@dhurta.org.

15 — GDPR Rights

Your Privacy Rights (GDPR — EU / EEA / UK Users)

If you are located in the European Economic Area, the United Kingdom, or Switzerland, the GDPR grants you the following rights. Because Dhurta Developer Browser processes no personal data on our servers, these rights are exercisable primarily over locally-stored data, which is entirely under your own control.

👁️
Right of Access (Art. 15)
Request a copy of any personal data we hold. Because we hold none on servers, local data can be found at dhurta://transparency.
✏️
Right to Rectification (Art. 16)
Request correction of inaccurate data. Local browser data can be edited directly from browser settings.
🗑️
Right to Erasure (Art. 17)
Request deletion of your personal data. Clear all browser data from Settings → Privacy → Clear Data. Uninstalling + deleting the profile directory removes everything.
📦
Right to Portability (Art. 20)
Export your data in machine-readable format. Export bookmarks, network logs (HAR), profiler traces, and workspace settings from their respective panels.
🚫
Right to Object (Art. 21)
Object to processing of your data. Because we process nothing on our servers, there is nothing to object to on our end.
⏸️
Right to Restrict (Art. 18)
Restrict processing. Local processing can be restricted by modifying settings or using Ghost Mode for session isolation.

To exercise any of these rights, contact our Privacy team at contact@dhurta.org or contact@dhurta.org. You also have the right to lodge a complaint with your national Data Protection Authority (DPA).

Legal Basis for Processing

To the extent that any processing of personal data occurs (such as processing local browser data to provide browser functionality), the legal basis is performance of a contract — the browser cannot function without storing some data locally on your device — and legitimate interest in providing the service you have installed. We do not process personal data for marketing, profiling, or automated decision-making.

16 — CCPA Rights

Your Privacy Rights (CCPA — California Users)

  • Right to Know: See Section 04 for the complete data audit. We collect no personal data on our servers.
  • Right to Delete: Clear all browser data at any time from Settings → Privacy → Clear Browsing Data. No server-side data to request deletion of.
  • Right to Opt Out of Sale: Dhurta does not sell, rent, lease, or trade personal information. There is nothing to opt out of.
  • Right to Non-Discrimination: We will not discriminate against you for exercising any of your CCPA rights.
  • Right to Correct: Local browser data can be managed directly from the browser interface.
  • Right to Limit Use of Sensitive Personal Information: We do not collect or process sensitive personal information as defined under the CPRA.
Do Not Sell or Share

Dhurta does not sell, share, rent, or otherwise disclose personal information to third parties for any purpose. We have no advertising partners, no data brokers, and no revenue model based on user data. This applies to both the consumer and developer browser products.

17 — Universal Rights

Universal Rights for All Users

  • Full transparency: Open dhurta://transparency at any time to see every file the browser has written to your disk, its size, and when it was last modified.
  • Immediate data deletion: Clear all browsing data at any time from Settings → Privacy → Clear Browsing Data. No waiting period, no support ticket, no approval required.
  • Data portability: Export bookmarks, history (JSON), network logs (HAR), and profiler traces from their respective panels.
  • Profile portability: Your profile directory is a standard filesystem folder. Copy it, back it up, move it to another machine, or archive it freely.
  • Complete erasure: Uninstalling the browser and deleting your profile directory removes all data. No residual server-side data exists.
  • No dark patterns: We will not use confusing interfaces or psychological manipulation to discourage you from exercising your privacy rights.
